# DevOps1126 ― Git × Docker × CI/CD デモ

DevOps全体像理解研修（2026年11月26日）のデモ用リポジトリです。
「ブランチ運用のとき、コンテナはどう作るのか」という宿題の答えを、GitHub Actions で動かして見せます。

**自分のリポジトリで同じことを試す手順は [docs/handson.md](docs/handson.md) にあります。**

## 一言で

**ブランチはイメージの出どころ。環境の違いは環境変数。**

| ブランチ | 何が起きるか | 動く場所 |
|---|---|---|
| 個別ブランチ | 手元のソースをコンテナにつなぐ（`compose.yaml`） | 各自のPC |
| `dev` | テスト → **イメージを1回だけビルド**（コミットIDの札付き） | 開発環境 |
| `verification` | テスト → 同じイメージを取ってくる（作り直さない） | 検証環境 |
| `main` | テスト → 同じイメージを取ってくる → **承認待ち** | 本番環境 |

アプリは「いまどの環境で、どの設定で動いているか」を返すだけです。

```
環境       : staging
DB接続先   : staging-db
パスワード : 設定なし
ビルド     : 1a2b3c4
```

`ビルド` はイメージに焼き込んだ値なので、3つの環境で同じになります。
`環境` と `DB接続先` は起動するときに渡す値なので、環境ごとに変わります。

## ファイル

| ファイル | 役割 |
|---|---|
| `app/app.py` | アプリ本体（Python標準ライブラリだけ） |
| `tests/test_app.py` | 単体テスト |
| `Dockerfile` | イメージの作り方。環境ごとの値は書かない |
| `compose.yaml` | 手元で動かす設定（ソースをバインドマウント） |
| `.github/workflows/pipeline.yml` | CI/CD の流れ |
| `docs/handson.md` | 自分のリポジトリで再現する手順書 |

## 注意：PR でマージする場合

GitHub の PR でマージすると、マージコミットという**新しいコミット**ができるため、そのコミットIDのイメージはありません（デプロイが「イメージがありません」で止まります）。
このデモではブランチを fast-forward で進めていますが、実際の運用では次のどちらかを選びます。

- **A. 1回ビルドして運ぶ**：PR のマージではなく、「どのイメージを出すか」をタグで指定して昇格させる仕組みにする
- **B. 環境ごとにビルドする**：マージのたびにビルドする。ロックファイルやベースイメージのバージョン固定で、中身のずれを防ぐ

どちらが正しいかは、アプリが設定を**いつ読むか**（起動時か、ビルド時か）で決まります。
